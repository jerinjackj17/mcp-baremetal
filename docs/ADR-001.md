# ADR-001: raw JSON-RPC instead of the MCP SDK

Status: accepted, 2026-10-13

## Context

This project has to demonstrate understanding of the MCP protocol, not just
use it. An SDK hides the wire format, which is exactly the part an
interviewer asks about: walk me through a tools/call round trip.

## Options

**Official MCP Python SDK.** Fastest to build, least instructive. The
protocol becomes a black box and the demo becomes "I called the SDK."

**Hand-rolled JSON-RPC 2.0.** About 90 lines for the dispatcher. Every
method, error code, and scope check is visible. Any HTTP client in any
language can drive the server, which the stdlib-only client proves.

## Decision

Hand-rolled. The server implements `initialize`, `tools/list`, `tools/call`,
and `ping` per JSON-RPC 2.0 with MCP-shaped payloads, over HTTP instead of
stdio. Deliberate demo tradeoff: browsers cannot do stdio.

## Consequences

No SSE streaming or stdio transport in this repo. Both are thin adapters
over the same dispatcher.

Error codes stay in the JSON-RPC ranges (-32700 to -32603, plus -32001 and
-32003 for auth), so standard tooling stays compatible.

If the spec surface grows (resources, prompts), each method is one function
to add. The dispatcher does not care.
